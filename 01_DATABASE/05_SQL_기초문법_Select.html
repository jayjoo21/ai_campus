0. SQL과 관계형 데이터베이스를 먼저 이해하기

SQL(Structured Query Language)은 관계형 데이터베이스에 저장된 데이터를 조회하고 관리하는 언어입니다. SQL 문법을 외우기 전에 “데이터가 어디에 어떤 모양으로 저장되어 있는가”를 이해하면 쿼리를 훨씬 쉽게 읽을 수 있습니다.

데이터베이스 구조를 네 단계로 보기
🗄️Schema테이블을 묶는 논리적 공간
▦Table같은 종류의 데이터를 저장하는 표
↔Row고객 1명·결제 1건처럼 한 건
↕Column이름·금액·날짜 같은 속성
SQL은 “어느 스키마의 어느 테이블에서 어떤 행과 열을 가져올 것인가?”를 표현하는 언어라고 생각하면 쉽습니다.

Primary Key(PK)

한 테이블 안에서 각 행을 유일하게 구분하는 대표 키입니다. 예: customers.customer_id.

Foreign Key(FK)

다른 테이블의 PK를 참조하는 연결 키입니다. 예: accounts.customer_id.

Grain(그레인, 한 행의 단위)

Grain은 데이터에서 한 행(Row)이 정확히 무엇을 나타내는지를 뜻합니다. 예를 들어 customers는 고객 1명, card_payments는 카드결제 1건, stock_prices는 종목 1개 × 거래일 1일이 한 행입니다. JOIN이나 GROUP BY 전에 Grain을 확인하면 중복 행과 잘못된 합계를 예방할 수 있습니다.

Grain을 어떻게 읽을까?
customers → 한 행 = 고객 1명
card_payments → 한 행 = 카드결제 1건
stock_prices → 한 행 = 종목코드 1개 × 거래일 1일의 주가 1건

같은 테이블이라도 GROUP BY customer_id를 적용하면 결과의 Grain은 고객 1명으로 바뀝니다. 따라서 “원본 테이블의 Grain”과 “최종 조회 결과의 Grain”을 구분해서 봐야 합니다.

3. 별칭(Alias)과 표현식 — 결과를 읽기 쉽게 만들기

별칭은 컬럼이나 테이블에 현재 조회에서만 사용하는 임시 이름을 붙입니다. DB 원본 컬럼명은 바뀌지 않습니다.

SELECT
    stock_code AS ticker,
    close_price AS close,
    volume AS trading_volume
FROM stock_data.stock_prices
LIMIT 20;

계산식에도 별칭을 붙일 수 있다

SELECT
    payment_id,
    amount,
    amount * 0.01 AS fee_estimate
FROM fintech_fraud_lab_class.card_payments
LIMIT 20;
해석
fee_estimate는 DB에 새 컬럼을 저장한 것이 아니라 조회 결과에서만 생성된 계산 컬럼입니다.

4. WHERE — 조건에 맞는 행만 선택하기

SELECT가 필요한 열을 고른다면 WHERE는 조건에 맞는 행을 고릅니다. 금융 데이터는 행 수가 크기 때문에 분석 전에 기간·상태·종목 등을 SQL에서 먼저 제한하는 경우가 많습니다.

WHERE는 큰 데이터에서 필요한 행만 통과시키는 필터
결제 A · 25,000원 · 국내
결제 B · 750,000원 · 해외
결제 C · 31,000원 · 국내
결제 D · 520,000원 · 온라인
결제 E · 14,000원 · 국내
WHERE amount >= 500000조건을 만족한 B와 D만 결과로 전달

비교 연산자

연산자뜻금융 데이터 예
=같다stock_code = '005930'
<>, !=같지 않다status <> 'CLOSED'
>, >=크다 / 이상amount >= 500000
<, <=작다 / 이하credit_score < 600

AND / OR / NOT

SELECT payment_id, customer_id, amount, is_overseas, is_online
FROM card_payments
WHERE amount >= 500000
  AND (is_overseas = 1 OR is_online = 1)
LIMIT 100;
AND와 OR를 섞을 때는 괄호를 사용
연산자 우선순위를 기억하고 있더라도 괄호로 의도를 명시하면 쿼리를 읽는 사람이 조건을 오해할 가능성이 줄어듭니다.

IN / BETWEEN / LIKE

-- 여러 후보값 중 하나
SELECT customer_id, risk_segment
FROM customers
WHERE risk_segment IN ('HIGH', 'MEDIUM');

-- 범위의 양 끝값 포함
SELECT customer_id, credit_score
FROM customers
WHERE credit_score BETWEEN 600 AND 750;

-- 문자열 패턴
SELECT stock_code, company_name
FROM stock_data.stocks
WHERE company_name LIKE '%전자%';

기간과 상태를 함께 제한하는 예

SELECT payment_id, customer_id, payment_at, amount, is_approved, fraud_label
FROM fintech_fraud_lab_class.card_payments
WHERE payment_at >= '2026-01-01'
  AND payment_at <  '2026-08-01'
  AND is_approved = 1
ORDER BY payment_at
LIMIT 200;

5. ORDER BY와 LIMIT — 결과의 순서와 크기를 제어하기

관계형 DB는 ORDER BY가 없으면 결과 행의 순서를 보장하지 않습니다. 주가처럼 시계열 순서가 중요한 데이터는 날짜 기준 정렬을 명시해야 합니다.

SELECT stock_code, trade_date, close_price, volume
FROM stock_data.stock_prices
WHERE stock_code = '005930'
ORDER BY trade_date ASC
LIMIT 100;

ASC

오름차순. 날짜는 과거 → 최근, 숫자는 작은 값 → 큰 값.

DESC

내림차순. 최근 날짜나 큰 금액을 먼저 보고 싶을 때 사용합니다.

LIMIT

현재 조회 결과에서 반환할 최대 행 수입니다. 원본 행을 삭제하지 않습니다.

둘 이상의 기준으로 정렬

SELECT customer_id, payment_at, amount
FROM card_payments
ORDER BY customer_id ASC, payment_at DESC
LIMIT 100;

먼저 고객번호순으로 묶어 보이고, 같은 고객 안에서는 최신 결제를 먼저 보여줍니다.

6. DISTINCT와 NULL — 실제 값과 “값 없음”을 구분하기

DISTINCT로 실제 코드값부터 확인

범주형 컬럼의 값을 추측해 WHERE 조건을 만들지 말고, 실제 저장값을 먼저 확인합니다.

SELECT DISTINCT payment_channel
FROM card_payments
ORDER BY payment_channel;

SELECT DISTINCT auth_method
FROM card_payments
ORDER BY auth_method;
NULL, 0, 빈 문자열은 서로 다른 값
NULL값이 없거나 아직 모름
IS NULL로 검사
0숫자 값 0이 실제로 저장됨
= 0으로 비교
''문자열은 존재하지만 내용이 없음
= ''로 비교

잘못된 방식

WHERE device_id = NULL

올바른 방식

WHERE device_id IS NULL
SELECT payment_id, customer_id, device_id, payment_at
FROM card_payments
WHERE device_id IS NULL
LIMIT 50;

COUNT(*)와 COUNT(column)의 차이

SELECT
    COUNT(*) AS all_rows,
    COUNT(device_id) AS rows_with_device,
    COUNT(*) - COUNT(device_id) AS rows_without_device
FROM card_payments;
핵심
COUNT(*)는 모든 행을 세지만 COUNT(device_id)는 device_id가 NULL이 아닌 행만 셉니다.

7. 집계 함수 — 여러 행을 하나의 요약값으로 계산하기

집계 함수는 데이터의 규모와 범위를 빠르게 파악하는 데 유용합니다. 처음 보는 테이블이라면 행 수·최초일·최종일·평균·합계부터 확인하면 데이터 상태를 빠르게 이해할 수 있습니다.

함수의미금융 예
COUNT(*)행 수카드결제 총 건수
SUM(amount)합계총 결제금액
AVG(amount)평균평균 결제금액
MIN()최솟값최초 거래일
MAX()최댓값최종 거래일
SELECT
    COUNT(*) AS row_count,
    MIN(payment_at) AS min_payment_at,
    MAX(payment_at) AS max_payment_at,
    AVG(amount) AS avg_amount,
    SUM(amount) AS total_amount
FROM card_payments;
주의
평균값 하나만 보면 분포를 놓칠 수 있습니다. 예를 들어 대부분이 2만원 결제인데 일부 1천만원 결제가 섞이면 평균이 크게 올라갑니다. SQL 기초 단계에서는 평균과 함께 최소·최대·건수를 같이 확인하는 습관이 좋습니다.

8. GROUP BY와 HAVING — 같은 값을 묶어 그룹별 통계 보기

GROUP BY는 같은 값을 가진 행을 그룹으로 묶고 그룹별 COUNT·SUM·AVG 등을 계산합니다.

GROUP BY를 “바구니에 나눠 담고 바구니별로 계산”이라고 생각하기
fraud_label = 0
정상 · 정상 · 정상 · 정상 · …
COUNT = 정상 건수
fraud_label = 1
사기 · 사기 · …
COUNT = 사기 건수
결과
라벨마다 한 행씩
그룹별 분포 비교

FDS 라벨 분포

SELECT fraud_label, COUNT(*) AS rows
FROM card_payments
WHERE is_approved = 1
GROUP BY fraud_label
ORDER BY fraud_label;

종목별 보유 데이터 기간

SELECT
    stock_code,
    COUNT(*) AS trading_days,
    MIN(trade_date) AS min_date,
    MAX(trade_date) AS max_date
FROM stock_data.stock_prices
GROUP BY stock_code
ORDER BY trading_days DESC
LIMIT 20;

WHERE와 HAVING의 차이

SELECT
    customer_id,
    COUNT(*) AS payment_count,
    AVG(amount) AS avg_amount
FROM card_payments
WHERE is_approved = 1
GROUP BY customer_id
HAVING COUNT(*) >= 10
ORDER BY payment_count DESC;

WHERE

그룹화 전의 원본 행에 조건을 적용합니다.

HAVING

GROUP BY 이후 만들어진 집계 결과에 조건을 적용합니다.

9. CASE WHEN — 조건에 따라 값을 분류하기

CASE는 Python의 if/elif/else와 비슷하게 조건에 따라 다른 값을 반환합니다. 원본 값을 삭제하거나 바꾸는 것이 아니라 조회 결과에 새 분류값을 만들 수 있습니다.

SELECT
    customer_id,
    credit_score,
    CASE
        WHEN credit_score >= 800 THEN 'VERY_HIGH'
        WHEN credit_score >= 700 THEN 'HIGH'
        WHEN credit_score >= 600 THEN 'MID'
        ELSE 'LOW'
    END AS score_band
FROM customers
LIMIT 50;

순서가 중요한 이유

CASE는 위에서 아래로 조건을 검사하고 처음 참이 되는 분기를 선택합니다.

예시 점수구간은 문법 이해용
실제 신용평가의 Binning이나 Scorecard 구간은 데이터 분석·모델링 절차를 통해 별도로 정의해야 합니다.

10. 날짜와 기간 조건 — 금융 데이터에서 시점을 정확히 다루기

금융 AI에서는 “그 시점에 실제로 알 수 있었던 데이터인가?”가 중요합니다. 날짜 조건을 잘못 잡으면 미래 정보가 과거 학습 데이터에 섞이는 Data Leakage가 발생할 수 있습니다.

[시작, 종료) 형태를 권장하는 이유

WHERE payment_at >= '2026-01-01'
  AND payment_at <  '2026-08-01'

DATETIME에는 시·분·초가 포함되므로 종료일의 자정 직전까지 억지로 계산하기보다 시작 포함, 다음 구간 시작 미포함 형태가 경계를 명확하게 만듭니다.

SELECT application_id, customer_id, application_at, approved, default_12m_label
FROM loan_applications
WHERE application_at >= '2025-01-01'
  AND application_at <  '2026-08-01'
ORDER BY application_at;

날짜 함수로 분포 탐색

SELECT
    YEAR(payment_at) AS payment_year,
    MONTH(payment_at) AS payment_month,
    COUNT(*) AS rows
FROM card_payments
GROUP BY YEAR(payment_at), MONTH(payment_at)
ORDER BY payment_year, payment_month;
Point-in-Time의 출발점
날짜 조건은 “언제의 데이터를 볼 것인가”를 통제하는 가장 기본적인 장치입니다. 특정 시점 기준 최신정보를 붙이는 As-of Join은 Window 함수와 Point-in-Time 단원에서 더 확장할 수 있습니다.

11. SQL의 논리 처리 순서 — SELECT부터 쓰지만 FROM부터 생각하기

SQL 문장은 SELECT부터 작성하지만, 데이터가 처리되는 논리적 흐름을 이해하면 GROUP BY·HAVING·별칭 오류를 이해하기 쉬워집니다.

논리적 처리 흐름
1. FROM
2. WHERE
3. GROUP BY
4. HAVING
5. SELECT
6. ORDER BY
7. LIMIT
SELECT customer_id, COUNT(*) AS payment_count
FROM card_payments
WHERE payment_at >= '2026-01-05'
  AND payment_at <  '2026-01-06'
GROUP BY customer_id
HAVING COUNT(*) >= 50
ORDER BY payment_count DESC
LIMIT 20;
FROMcard_payments에서 출발 WHERE지정한 하루의 결제만 남김 GROUP BY고객별로 묶음 HAVING50건 이상인 고객 그룹만 남김 SELECT고객번호와 건수를 결과 컬럼으로 구성 ORDER BY결제건수 큰 순서로 정렬 LIMIT상위 20행만 반환
최종 결과의 Grain
이 쿼리에서 결과 한 행은 고객 1명입니다. GROUP BY를 사용하면 원본의 한 행 의미가 바뀔 수 있으므로 항상 최종 Grain을 다시 확인합니다.

12. 자주 틀리는 SQL 패턴과 수정 방법

① 존재하지 않는 컬럼 추측

먼저 DESCRIBE table_name으로 실제 컬럼명을 확인합니다.

② NULL을 = 로 비교

= NULL이 아니라 IS NULL 또는 IS NOT NULL을 사용합니다.

③ 문자열 따옴표 누락

문자열과 날짜는 일반적으로 작은따옴표로 감쌉니다. 예: 'HIGH', '2026-01-01'.

④ ORDER BY 없이 시계열 사용

주가·거래내역은 날짜순을 가정하지 말고 명시적으로 정렬합니다.

⑤ WHERE와 HAVING 혼동

원본 행 조건은 WHERE, 집계 결과 조건은 HAVING으로 구분합니다.

⑥ SELECT * 남용

분석에 필요한 컬럼을 명시해 데이터량과 개인정보 노출을 줄입니다.

오류가 나면 이 순서로 확인

SQL 디버깅 순서
1현재 DBSELECT DATABASE()
2테이블 존재SHOW TABLES
3컬럼 구조DESCRIBE
4조건값 확인DISTINCT

13. SQL에서 금융 AI Notebook으로 데이터를 넘기는 기준

SQL의 역할은 모든 분석을 끝내는 것이 아니라 필요한 원천 데이터를 정확한 범위로 가져오는 것입니다. Feature Engineering·통계검정·머신러닝·Embedding은 이후 Python 단계에서 처리할 수 있습니다.

데이터 준비 파이프라인
1. Schema/Table 확인원천 데이터 위치 확인
2. SELECT필요 컬럼만 선택
3. WHERE기간·대상·상태 제한
4. SQL 품질 확인건수·기간·NULL·코드값 확인
5. Python전처리·Feature·모델링 수행

FDS 데이터 예

SELECT
    payment_id,
    customer_id,
    payment_at,
    amount,
    payment_channel,
    auth_method,
    country,
    ip_country,
    is_overseas,
    is_online,
    fraud_label
FROM fintech_fraud_lab_class.card_payments
WHERE is_approved = 1
  AND payment_at >= '2026-01-01'
  AND payment_at <  '2026-08-01'

Feature와 Target을 구분
fraud_label은 정답(Target)이며, 모델 입력 Feature와 섞으면 안 됩니다. is_approved처럼 학습 대상 범위를 정하는 필터 컬럼도 모델 Feature로 사용할지 별도로 판단해야 합니다.

14. 종합 확인 문제

문제 1 — 삼성전자 주가 데이터의 건수와 기간 확인
SELECT
    stock_code,
    COUNT(*) AS rows,
    MIN(trade_date) AS min_date,
    MAX(trade_date) AS max_date
FROM stock_data.stock_prices
WHERE stock_code = '005930'
GROUP BY stock_code;
문제 2 — 승인 여부별 카드결제 건수 확인
SELECT is_approved, COUNT(*) AS rows
FROM fintech_fraud_lab_class.card_payments
GROUP BY is_approved
ORDER BY is_approved;
문제 3 — 승인된 결제의 사기 라벨 분포 확인
SELECT fraud_label, COUNT(*) AS rows
FROM fintech_fraud_lab_class.card_payments
WHERE is_approved = 1
GROUP BY fraud_label
ORDER BY fraud_label;
문제 4 — 대출신청 데이터의 최초일·최종일·건수 확인
SELECT
    COUNT(*) AS rows,
    MIN(application_at) AS min_application_at,
    MAX(application_at) AS max_application_at
FROM fintech_fraud_lab_class.loan_applications;
문제 5 — 현재 유효한 금융정책 문서를 문서유형별로 집계
SELECT doc_type, COUNT(*) AS rows
FROM fintech_fraud_lab_class.financial_policy_docs
WHERE is_current = 1
GROUP BY doc_type
ORDER BY rows DESC;
문제 6 — 해외 또는 온라인 고액결제 100건 조회
SELECT
    payment_id,
    customer_id,
    payment_at,
    amount,
    is_overseas,
    is_online
FROM fintech_fraud_lab_class.card_payments
WHERE amount >= 500000
  AND (is_overseas = 1 OR is_online = 1)
ORDER BY amount DESC
LIMIT 100;

15. 핵심 용어 사전

Schema테이블을 논리적으로 묶는 데이터베이스 공간.
Table같은 종류의 데이터를 행·열 구조로 저장한 객체.
Row테이블 안의 한 건의 레코드.
Column행을 설명하는 속성.
Grain데이터에서 한 행(Row)이 정확히 무엇을 나타내는지 정의한 단위. JOIN·GROUP BY 전후에 반드시 확인해야 합니다.
Primary Key각 행을 유일하게 식별하는 키.
Foreign Key다른 테이블의 키를 참조해 관계를 만드는 컬럼.
NULL값이 없거나 아직 알 수 없음을 나타내는 상태.
Aggregate여러 행을 COUNT·SUM·AVG 등 하나의 요약값으로 계산하는 것.
GROUP BY같은 값을 가진 행을 그룹으로 묶는 절.
HAVINGGROUP BY 이후 집계 결과에 적용하는 조건.
Data Leakage예측 시점에 알 수 없었던 정보가 학습에 섞여 성능이 비정상적으로 높아지는 문제.

SQL과 데이터 분석에서 자주 만나는 핵심 용어

문법만 알아도 SQL을 실행할 수는 있지만, 데이터 구조를 정확히 이해하려면 아래 용어를 함께 알아두는 것이 좋습니다.

Grain테이블의 한 행이 무엇을 의미하는지를 나타내는 분석 단위입니다. 예: 고객 1명, 결제 1건, 종목×거래일 1건.
Schema관련 테이블을 묶어 관리하는 논리적 공간입니다. MySQL에서는 Database와 거의 같은 의미로 사용됩니다.
Primary Key (PK)각 행을 유일하게 구분하는 대표 키입니다. 같은 PK 값은 중복될 수 없습니다.
Foreign Key (FK)다른 테이블의 PK를 참조하여 테이블 사이의 관계를 만드는 키입니다.
Cardinality테이블 관계에서 한쪽 행이 다른 쪽과 몇 개까지 연결되는지를 뜻합니다. 예: 고객 1명 : 계좌 여러 개 = 1:N.
PredicateWHERE amount > 100000처럼 참/거짓을 판단하는 조건식을 뜻합니다.
AggregationCOUNT, SUM, AVG처럼 여러 행을 하나의 요약값으로 계산하는 것입니다.
AliasAS를 이용해 컬럼이나 테이블에 조회 중 사용할 임시 이름을 붙이는 것입니다.
Filter조건에 맞는 행만 남기는 작업입니다. SQL에서는 주로 WHERE가 담당합니다.
Sort행의 순서를 정하는 작업입니다. SQL에서는 ORDER BY를 사용합니다.
Distinct중복값을 제거하고 서로 다른 값만 남기는 개념입니다.
NULL0이나 빈 문자열이 아니라 값이 없거나 아직 알 수 없음을 뜻합니다.
Target머신러닝이 맞히려는 정답 컬럼입니다. 예: fraud_label.
Feature모델이 예측에 사용하는 입력 변수입니다. 예: 결제금액, 해외결제 여부, 거래시간 등.
Data Leakage예측 시점에는 알 수 없던 미래 정보나 정답에 가까운 정보를 학습에 섞는 오류입니다.

Grain을 확인하는 가장 쉬운 질문
SQL을 작성하기 전에 “이 테이블의 한 행은 무엇인가?”, GROUP BY 후에는 “결과의 한 행은 무엇인가?”라고 확인합니다. 이 두 질문만 습관화해도 JOIN 중복과 잘못된 집계를 크게 줄일 수 있습니다.
